## 2026-05-31 — Empirical finding: ollama topic path is NOT ready (stub stays default)
- **Test:** ran `topics --backend ollama --model llama3.2:latest` over the seed-42 synthetic corpus (39 text docs) on the user's machine, compared to the stub baseline. Decision deferred — logging the result.
- **Quality — net WORSE than stub.** Two clusters formed: (1) `kitchen-renovation-notes` = all 5 kitchen docs ✓ (recovered, but slug converged by luck); (2) `kitchen-renovation` = **manuscript_v3.txt + manuscript_v2_BACKUP.txt** — i.e. two MANUSCRIPT files mislabeled "Kitchen Renovation" and filed into a kitchen cluster. `manuscript_v1` → "The Long Migration" became an orphan singleton (dropped by min_size≥2). **The Long Migration project was destroyed**, vs stub which recovers it cleanly ×3. Root cause: gen_corpus builds every doc body from the same kitchen-vocabulary LOREM (only `# title` differs), and llama3.2 weights body over title → manuscript reads as "kitchen". Real corpora won't fail this exact way, but it proves the model is content-dominated and doesn't anchor on the title.
- **Speed — unusable at scale.** 12m38s for 39 tiny files (~19s/doc). One synchronous call at a time, no concurrency. A real inherited drive (thousands of docs) is a non-starter at this rate.
- **Reliability.** 5/39 hit the 120s per-call timeout (all Misc noise); `_ground_truth.json` got read + tagged. tagged=32 skipped=2 errors=5.
- **Mechanism flaw:** clustering on `slug` is arbitrary — slug is a *second, independent* model output uncorrelated with the `topic` label. The `topic` field is cleaner but fragmented across ~10 surface variants (renovation / Kitchen Renovation / Home Renovation / cabinet renovation …). Confidence is a flat ~0.8 → can't filter noise.
- **Verdict:** stub remains the only validated + fast + trustworthy path; its markdown-H1 requirement doubles as a quality/noise gate, which is *why* it's clean. The ollama path runs but must not be presented as ready.
- **Phase 4.5 (deferred) to make ollama good:** (a) cluster on a *canonicalized topic label* not raw slug — two-pass gather→canonicalize-set→assign; (b) structural/quality noise gate (require a real title or shared dir) so shared-vocabulary noise doesn't merge — same prior that saved doc_version in near.py; (c) concurrency + short (~15s) timeout + smaller/faster model (qwen3:1.7b, gemma4:e4b). This is real work, not a config tweak.
